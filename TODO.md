# Pixa Agent – Project To-Do & Roadmap

Based on the recent features we've implemented and the current state of the codebase, here is a strategic roadmap to take Pixa Agent to the next level of stability and capability.

## 1. Agent Memory & Task Management
- [ ] **Native UI Checklist:** Currently, we instruct the agent to maintain a `.pixa/task-state.md` file for long tasks. We should build a native "Task Plan" UI component in the webview. The agent can use a new tool (`update_plan`) to visually check off items, keeping the workspace clean.
- [ ] **Stateful Loop Resumption:** If VS Code crashes or is closed mid-task, we currently save the chat history, but the active execution loop dies. Implement full execution-state serialization so the agent can resume a multi-step loop exactly where it left off on restart.
- [ ] **Automated Linter Feedback Loop:** Instead of relying on the system prompt to tell the agent to run `get_diagnostics`, intercept file edits natively. If an edit introduces a syntax or linter error, automatically feed that diagnostic back to the agent in the same turn before asking for user approval.

## 2. Chat UI & UX Enhancements
- [ ] **Syntax Highlighting in Chat:** Code blocks in the chat currently use basic `<pre>` tags. Integrate `shiki` or `highlight.js` to render code snippets using the user's active VS Code theme.
- [ ] **Drag-and-Drop Context:** Expand the `@file.ts` mention system to support dragging and dropping files or folders directly from the VS Code explorer into the chat composer.
- [ ] **One-Click "Copy Code":** Add a standard "Copy" button to the top-right of all code blocks generated by the agent.

## 3. Configuration & Integrations
- [ ] **MCP (Model Context Protocol) GUI:** Right now, users have to manually configure `pixa.mcpServers` in their `settings.json`. Create a simple UI settings panel in the webview to easily add, test, and manage MCP server connections.
- [ ] **Model Provider Auto-Discovery:** Automatically detect local inference servers (like Ollama or LM Studio) running on default ports and populate them in the model dropdown without requiring JSON configuration.

## 4. Architecture & Testing
- [ ] **E2E Extension Tests:** We rely on unit tests via `vitest`. We need to add VS Code Extension E2E tests (`@vscode/test-electron`) to programmatically simulate chat inputs, button clicks (like "Apply all"), and verify webview-to-host messaging doesn't break in future refactors.
- [ ] **RAG Indexing Optimization:** The `pixa.rebuildSemanticIndex` command runs synchronously. Move the semantic indexing pipeline to a dedicated Web Worker or background process so it doesn't degrade editor performance on massive monorepos.
- [ ] **Robust Telemetry / Error Tracing:** Replace `(e as Error).message` catches with a proper structured logging mechanism (e.g., an Output Channel in VS Code) so users can export logs when they encounter issues.

---
*This list prioritizes stability (resilience against crashes/errors), user experience (UI polish), and agent autonomy (better task chunking).*
